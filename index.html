🧠 Respuestas Conceptuales (Consigna)

1. ¿Por qué hashear contraseñas?

Almacenar contraseñas en texto plano es una de las vulnerabilidades más críticas en seguridad informática:

  • Protección ante filtraciones (Data Breaches): Si un atacante accede indebidamente a la base de datos o a copias de respaldo, solo obtiene cadenas de hashes irreversibles, impidiendo el uso de las contraseñas reales.
  • Propiedad unidireccional (One-Way): Calcular Hash = H(contraseña) es inmediato, pero es computacionalmente inviable deducir la contraseña original a partir del hash (H⁻¹(Hash)). La validación se hace comparando hashes.
  • Salting contra Tablas de Arcoíris (Rainbow Tables): Las funciones modernas agregan una secuencia pseudoaleatoria única (*Salt*) por contraseña, asegurando que usuarios con la misma clave tengan hashes distintos.
  • Resistencia a fuerza bruta: Algoritmos como scrypt y PBKDF2 introducen retardos y costos de memoria deliberados para impedir ataques automatizados masivos.

2. Ventajas de usar SQLite en este proyecto

  • Serverless: No requiere un servicio demonio escuchando en un puerto de red ni mantenimiento de procesos adicionales.
  • Cero configuración: Integrado nativamente en Python con import sqlite3 sin configuraciones de servidores externos.
  • Portabilidad total: Toda la base de datos reside en un único archivo autocontenido (tareas_db.sqlite), facilitando el respaldo y la entrega.
  • Garantía ACID: Asegura la consistencia y atomicidad de las transacciones ante apagados imprevistos.
