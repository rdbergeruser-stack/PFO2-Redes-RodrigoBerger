Sistema de Gestión de Usuarios

API REST desarrollada con Flask, persistencia relacional en SQLite3 y contraseñas protegidas con hashing criptográfico unidireccional y salt. Incluye cliente de consola interactivo y control de acceso por sesión.

🏛️ Institución: IFTS N.° 29
👤 Alumno: Rodrigo Berger
🛠️ Backend: Python 3 / Flask
🗄️ Persistencia: SQLite (usuarios.db)
🔒 Criptografía: Werkzeug (PBKDF2/scrypt)
Ver Repositorio en GitHub ↗ Ver Capturas de Pruebas ↓

1. Descripción del Proyecto y Arquitectura

// CLIENTE-SERVIDOR

🔑 1. Registro Seguro

Da de alta nuevos usuarios recibiendo credenciales vía JSON. Almacena contraseñas transformadas mediante hash criptográfico con salt aleatorio, garantizando que nunca se persistan en texto plano.

🚪 2. Inicio de Sesión

Endpoint de autenticación que contrasta las credenciales recibidas con el hash almacenado en SQLite mediante funciones seguras de verificación, habilitando la sesión del cliente sin comprometer la clave.

🔒 3. Listado Protegido

Consulta de todos los usuarios registrados. Está restringido a usuarios con sesión activa: si no se proveen credenciales válidas, retorna HTTP 401 Unauthorized. No expone hashes por seguridad.

📁 Componentes del Repositorio

  • servidor.py: Servidor API REST en Flask con endpoints /registro, /login y /usuarios, con conexión SQLite y CORS habilitado.
  • cliente.py: Cliente de consola en Python con menú interactivo (1 a 5) y manejo de sesiones para consumir la API.
  • usuarios.db: Archivo de base de datos relacional SQLite que almacena la tabla usuarios.
  • index.html: Esta página estática alojada en GitHub Pages con la presentación oficial y documentación del proyecto.
  • README.md: Documentación completa en formato Markdown con respuestas conceptuales y guías técnicas.

2. Estructura de la Base de Datos

// SQLITE (usuarios.db)

La persistencia se realiza íntegramente en un archivo autocontenido relacional denominado usuarios.db mediante la tabla usuarios:

Campo Tipo de Dato Restricciones Descripción
id INTEGER PRIMARY KEY AUTOINCREMENT Identificador numérico único y autoincremental de cada usuario.
usuario TEXT UNIQUE NOT NULL Nombre de usuario elegido para autenticarse (sin duplicados).
contrasena_hash TEXT NOT NULL Cadena de hash seguro con salt generada por Werkzeug (PBKDF2/scrypt).
fecha_registro TEXT NOT NULL Fecha y hora del sistema en la que se dio el alta (YYYY-MM-DD HH:MM:SS). 
-- Definición de la tabla en SQLite (servidor.py)
CREATE TABLE IF NOT EXISTS usuarios (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    usuario TEXT UNIQUE NOT NULL,
    contrasena_hash TEXT NOT NULL,
    fecha_registro TEXT NOT NULL
);

3. Especificación de Endpoints REST

// HTTP CONTRACT
POST /registro 201 Created

Registro de Usuarios

Da de alta un usuario y guarda su contraseña hasheada en SQLite.

Body JSON:

{
  "usuario": "Berger",
  "contraseña": "1234"
}

• 201 Created: Alta exitosa.
• 400 Bad Request: Datos incompletos.
• 409 Conflict: Usuario ya existente.

POST /login 200 OK

Inicio de Sesión

Valida credenciales comparando contra el hash almacenado.

Body JSON:

{
  "usuario": "Berger",
  "contraseña": "1234"
}

• 200 OK: Sesión iniciada con éxito.
• 401 Unauthorized: Usuario o clave incorrectos.

GET /usuarios 🔒 Protegido

Listado de Usuarios

Retorna todos los usuarios registrados. Requiere autenticación activa.

Headers requeridos:

X-Usuario: Berger
X-Contrasena: 1234

• 200 OK: Lista en JSON (id, usuario, fecha).
• 401 Unauthorized: Si no inició sesión.

4. Respuestas a Preguntas Conceptuales

// EVALUACIÓN TEÓRICA

1. ¿Por qué es fundamental hashear contraseñas en lugar de guardarlas en texto plano?

Guardar contraseñas en texto plano representa la vulnerabilidad más crítica en seguridad web. Las razones técnicas clave para utilizar funciones hash son:

  • Protección ante filtraciones de bases de datos (Data Breaches): Si un atacante extrae la base de datos o se filtra una copia de respaldo, solo obtendrá cadenas alfanuméricas ininteligibles, impidiendo que acceda a las claves reales de los usuarios o las reutilice en otros servicios.
  • Propiedad Unidireccional (One-Way): A diferencia del cifrado simétrico o asimétrico (reversible mediante claves de desencriptación), una función hash criptográfica es matemáticamente irreversible. Es inmediato calcular Hash = H(contraseña), pero resulta computacionalmente inviable deducir la contraseña original a partir del hash (H⁻¹(Hash)). Para autenticar, el servidor calcula el hash de lo ingresado en el login y lo compara contra el hash guardado, sin necesidad de conocer la clave en texto plano.
  • Defensa contra Tablas de Arcoíris (Rainbow Tables) mediante Salting: Algoritmos como PBKDF2 y scrypt (utilizados por werkzeug.security) generan automáticamente un Salt (secuencia aleatoria única por usuario) antes de calcular el hash. Esto garantiza que dos usuarios con la misma clave (ej: "1234") tengan hashes completamente distintos en la base de datos, inutilizando los diccionarios de hashes precalculados.
  • Resistencia a Ataques de Fuerza Bruta: Las funciones hash para contraseñas aplican costos iterativos de CPU y memoria deliberadamente para retardar los intentos masivos de adivinación automatizada.

2. ¿Cuáles son las ventajas de utilizar SQLite en este proyecto?

Para los requerimientos y alcance de este proyecto, SQLite aporta ventajas arquitectónicas determinantes frente a motores cliente-servidor como MySQL o PostgreSQL:

  • Arquitectura sin Servidor (Serverless): SQLite no corre como un proceso demonio o servicio en segundo plano ni requiere apertura de puertos de red. La biblioteca interactúa directamente con el archivo en disco, eliminando latencia de red en las consultas.
  • Cero Configuración (Zero-Configuration): No requiere credenciales de usuario de base de datos, administración de permisos de red ni cadenas complejas de conexión. Viene integrado de manera nativa en la biblioteca estándar de Python (import sqlite3).
  • Portabilidad Absoluta en un Único Archivo: Toda la base de datos (tablas, índices y registros) se almacena en el archivo usuarios.db. Esto permite que el proyecto se pueda clonar y ejecutar en cualquier equipo de inmediato sin instalar software adicional.
  • Garantía de Integridad ACID: Cumple estrictamente con las propiedades de Atomicidad, Consistencia, Aislamiento y Durabilidad (ACID), evitando corrupción de datos ante errores o cierres inesperados.
  • Consumo Mínimo de Recursos: Tiene una huella de memoria insignificante, lo que lo hace perfecto para arquitecturas ligeras de desarrollo local y pruebas de redes.

5. Guía de Ejecución Local

// COMANDOS DE CONSOLA

📦 1. Requisitos e Instalación

Instalar las dependencias necesarias en la consola:

pip install flask requests werkzeug

🚀 2. Iniciar el Servidor API

En una primera terminal:

python servidor.py

El servidor quedará a la escucha en http://localhost:5000 inicializando automáticamente usuarios.db.

💻 3. Iniciar el Cliente de Consola

En una segunda terminal distinta:

python cliente.py
