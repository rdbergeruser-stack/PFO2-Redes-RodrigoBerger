Sistema de Gestión de Tareas

API REST desarrollada en Flask con autenticación segura, contraseñas hasheadas (scrypt/PBKDF2), persistencia en SQLite y cliente de consola.

Alumno: Rodrigo Berger
Servidor: Flask + SQLite
Seguridad: Werkzeug Password Hash
Cliente: Python Consola

Arquitectura

Servidor Flask (`servidor.py`)

API REST funcional que gestiona rutas de registro, inicio de sesión, pantalla HTML de bienvenida y administración de tareas.

Seguridad Criptográfica

Hasheo con salt aleatorio en Werkzeug. Las contraseñas jamás se almacenan en texto plano en la base de datos.

Persistencia SQLite (`tareas_db.sqlite`)

Tablas relacionales usuarios y tareas vinculadas por claves foráneas, con transacciones seguras ACID.

Cliente de Consola (`cliente.py`)

Interfaz interactiva por línea de comandos para que el usuario pueda registrarse, ingresar y operar con la API.

Respuestas Conceptuales

1. ¿Por qué hashear contraseñas?

Almacenar contraseñas en texto plano es una de las vulnerabilidades más críticas. El hashing criptográfico es fundamental por:

  • Protección ante filtraciones de datos (Data Breaches): Si un atacante accede indebidamente a la base de datos o respaldos, solo obtiene hashes ininteligibles, impidiendo el uso de las claves reales de los usuarios.
  • Propiedad unidireccional (One-Way): Calcular Hash = H(contraseña) es directo, pero es inviable matemáticamente revertir H⁻¹(Hash) para conocer la clave. La validación se hace comparando hashes.
  • Salting contra Tablas de Arcoíris (Rainbow Tables): La librería añade una secuencia pseudoaleatoria única (*Salt*) por contraseña, asegurando que dos usuarios con la misma clave generen hashes distintos.
  • Resistencia a fuerza bruta: Algoritmos como scrypt o PBKDF2 agregan costo computacional deliberado para dificultar ataques masivos automatizados.

2. Ventajas de usar SQLite en este proyecto

  • Serverless: No necesita un demonio ni servicio corriendo en un puerto de red. La biblioteca interactúa directamente con el archivo.
  • Cero configuración: Integrado nativamente en Python con import sqlite3, sin dependencias de administración de motores externos.
  • Portabilidad total: Toda la base de datos es un único archivo autocontenido (tareas_db.sqlite), facilitando su distribución y corrección.
  • Garantía ACID: Asegura la consistencia y aislamiento de los datos ante cierres inesperados.
